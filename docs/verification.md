## PostgreSQL и устойчивость

Проверены повторные миграции с checksum/advisory lock, эксклюзивный экземпляр, атомарное сохранение сценария, конфликт устаревшей версии, архив и восстановление, уникальность имён, пагинация, неизменяемые версии окружений/ресурсов и снимки прогонов.

Проверены правила первого завершённого, первого успешного и ручного сохранения, объединение двух причин в одном объекте, идемпотентное завершение, гонка сохранения/удаления и защита закреплённой записи. Тест учитывает оба допустимых исхода гонки: удаление раньше сохранения либо сохранение раньше отклонённого удаления.

При отказе записи начала попытки внешний HTTP-запрос не отправляется. При отказе записи уже полученного результата приложение показывает отсутствие подтверждения и повторяет только запись. Потерянный ответ команды и последующий явный повтор используют один ключ и один внешний эффект. Ключ сохраняется также при обновлении CSRF-сессии после перезапуска сервера.

Принудительное завершение отдельного Go-процесса оставляет сохранённый ручной комментарий, переводит неизвестный вызов и прогон в `interrupted` после запуска и не отправляет вызов повторно. Очистка `sessionStorage` при живом backend восстанавливает текущий прогон из БД без новой команды запуска.

## Протоколы и секреты

HTTP проверен с параметрами, телом, ожидаемым 404, исходным 302 без перехода, тайм-аутом и ограничением размера. gRPC проверен с reflection и offline proto bundle с импортами, ожидаемым `NOT_FOUND`, trailers, отказом streaming, отсутствующими/недопустимыми импортами, тайм-аутом, отменой и большим ответом. Реальные HTTP/gRPC mTLS-серверы принимают корректную пару; неправильные CA, hostname, ключ и отсутствие клиентского сертификата отклоняются.

SQL проверен на отдельной целевой БД: параметры с кавычками, большие numeric, SQL `NULL` и JSON `null`, JSONB, запись с affected rows, ошибка прав, запрет нескольких statements, отмена, тайм-аут, 1000 строк и 5 MiB. Миграции приложения в целевой БД отсутствуют. Подстановки typed SQL сохраняют точность, SQL-текст не шаблонизируется.

Сравнение проверено для структуры JSON, больших чисел, порядка массивов, типов, текста CRLF/LF, HTTP-статуса, ожидаемого gRPC-кода, SQL-типов и числа строк. Неполный результат не даёт совпадения. UI выводит HTML как текст, отличает `NULL` от пустой строки и показывает ожидание выполненной версии.

Проверены AES-GCM с неверным ключом/associated data, write-only API, явное пустое значение и очистка секрета, запрет секретов в URL и неподходящих полях, неизвестные/циклические переменные, CRLF-инъекция через общий заголовок. Отражённый токен скрыт в API и сохранённом PostgreSQL-результате. Маскирование учитывает JSON-экранирование и вложенное JSON-тело. Host, Origin, CSRF и JSON content type проверены отдельно.

## Сквозные сценарии Chromium

1. Через UI создаются окружение, три ресурса, папка, кейс и смешанный шаг. Проверяются ошибки JSON/SQL-параметра у поля и сохранение введённого текста, защита несохранённых изменений, пробный вызов без прогона, три протокола, ручные статусы/комментарии, первый failed, первый passed, ручное сохранение, старый снимок, архив, восстановление и перезапуск бинарника.
2. Процесс останавливается во время внешнего запроса. Проверяются комментарий, `interrupted`, история и счётчик внешних эффектов.
3. Проверяются русская сортировка кириллицы/латиницы и страницы, перенос архивного кейса вниз, перестановка ручных шагов, конфликт редактора, разные окружения, маскирование секрета, потеря ответа и повтор команды, две отдельные попытки mismatch/match и успешный итог по последней.

Сквозные БД создаются с уникальными именами и удаляются после тестов; рабочая `qag` не используется. Скриншоты локальной проверки находятся в исключённой из Git `.local/`, диагностические Playwright-артефакты — в `web/test-results/`.

## Резервная копия

`TestBackupRestoreCatalogHistoryAndSecret` выполняет бинарный `pg_dump`/`pg_restore` между двумя отдельными временными БД. Проверяется фактическое имя каждого подключения, каталог, история, комментарии, причины сохранения, миграции и расшифровка ресурса исходным мастер-ключом. Другой ключ отклоняется. Рабочие данные не удаляются и не восстанавливаются поверх существующей БД.

Инструкции: [README](../README.md), [работа с приложением](usage.md), [эксплуатация и восстановление](operations.md). Ограничения первой версии: один локальный пользователь, unary gRPC, PostgreSQL для SQL, явные запуски, лимиты ответа и времени.
