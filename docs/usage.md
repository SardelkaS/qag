# Работа с qag

## Встроенный пример

Пункт «Встроенный пример» закреплён над папками на вкладках каталога и архива. Он открывает кейс «Пример: HTTP, gRPC и PostgreSQL» и автоматически выбирает системное окружение. Кейс и его ресурсы доступны только для чтения. Пробные вызовы, ручные статусы, комментарии и история работают так же, как у собственных кейсов. При возврате к пользовательскому кейсу восстанавливается прежнее окружение; несохранённые правки защищены обычным диалогом перехода.

Нажмите «Начать прогон» и последовательно выполните пять шагов:

1. HTTP `GET /items/example-001` ресурса `DEMO_HTTP` возвращает запись из БД.
2. gRPC `qag.demo.v1.DemoService/GetItem` ресурса `DEMO_GRPC` возвращает ту же запись по reflection.
3. SQL-ресурс `DEMO_SQL` читает `qag_demo.items` параметризованным запросом. Ожидаемая сумма — точное значение `9007199254740993.125`.
4. Два запроса отсутствующего ID ожидают HTTP `404` и gRPC `NOT_FOUND`. Совпадение ожидаемой ошибки считается успешным сравнением.
5. Ручной шаг предлагает сопоставить результаты трёх протоколов и записать итог.

После проверки каждого шага выберите «Пройден», сохраните комментарии и завершите прогон. Успешное сравнение вызова само не выставляет ручной статус. Первый успешный прогон может получить сразу две причины сохранения: «Первый прогон» и «Первый успешный».

HTTP использует основной адрес приложения: `http://127.0.0.1:8080/demo/v1/items/example-001`. Исходный proto доступен по `/demo/v1/demo.proto`; gRPC по умолчанию слушает `127.0.0.1:9091`. Чтение выполняется из настоящей PostgreSQL через отдельную роль: при недоступности таблицы сервис возвращает HTTP `503` или gRPC `UNAVAILABLE`. SQL-роли запрещены чтение служебной схемы `qag` и изменение объектов `qag_demo`.

## Собственный сценарий

Создайте окружение в разделе «Окружения и ресурсы», затем именованные ресурсы. Вернитесь в каталог, создайте папку и тест-кейс. В редакторе добавьте шаги, описания и вызовы. Заголовок шага необязателен. Стрелки меняют авторский порядок шагов и вызовов; каталог сортируется по русскому алфавиту без учёта регистра.

«Сохранить» записывает весь сценарий одной транзакцией. Номер версии меняется после записи. Ошибка или конфликт с другой вкладкой оставляет введённый текст в форме. Перед переходом из изменённого сценария можно сохранить изменения, отбросить их или остаться. Пробный вызов использует сохранённую версию; при наличии правок приложение сначала предлагает их сохранить.

Для сохранения кейса не требуется заполнять пользовательские поля: можно оставить пустые шаги, ресурс, ожидание, HTTP-статус или незаконченный JSON/SQL-параметр. При пустом имени приложение выбирает свободное «Новый тест-кейс», «Новый тест-кейс 2» и далее. После сохранения замечания готовности показываются отдельно. Они запрещают полный прогон, но позволяют пробный запуск уже готового блока. Перед запуском проверяются также выбранное окружение и подстановки. Полностью ручному шагу достаточно описания, ожидаемого текста или изображения.

В поле «Ресурс» выбираются только ресурсы текущего окружения с подходящим протоколом. Если сохранённое имя отсутствует в другом окружении, оно остаётся видимым как недоступное: черновик можно сохранить, а перед запуском нужно исправить выбор. Ввод `AI_GW_SERVISE/task` по-прежнему выделяет имя ресурса и путь.

## Изображения и тема

В ожидаемом результате шага и каждого HTTP/gRPC/PostgreSQL-вызова есть «+ Изображения». Выберите PNG, JPEG или WebP, при желании добавьте подписи и поменяйте порядок стрелками. Допускается до 10 изображений на одно ожидание, до 10 MiB и 20 миллионов пикселей на файл. Сервер проверяет содержимое файла. Миниатюра открывается в полном размере, Escape закрывает просмотр. Изображения служат эталонами для ручного сравнения и не влияют на автоматический статус совпадения.

Удаление изображения из текущего сценария сохраняет его в прежних прогонах и пробных попытках вместе с прежней подписью и порядком. Галереи доступны в прогоне, истории и режиме просмотра архивного кейса; там их нельзя менять.

В верхней панели выберите «Светлая тема», «Тёмная тема» или «Как в системе». Выбор сохраняется в браузере независимо от сценария. Переключение не сбрасывает ввод; при запрете browser storage тема работает в текущей вкладке. Запрос, ожидание и ответ разделены подписями и линиями в обеих темах.

Папка целиком перемещается на вкладку «Архив». Архивный кейс остаётся в своей папке, тускнеет и располагается после активных. Архив доступен для чтения и просмотра истории. Восстановление папки сохраняет собственные архивные флаги её кейсов.

## Подключения и подстановки

| Поле | Пример | Поведение |
|---|---|---|
| Имя ресурса | `AI_GW_SERVISE` | Уникально внутри выбранного окружения |
| Базовый URL | `https://gateway.local/api` | Содержит общий путь `/api` |
| Путь HTTP-блока | `AI_GW_SERVISE/task` | Редактор выделит ресурс и путь; запрос уйдёт в `/api/task` |
| Переменная окружения | `TASK_ID=123` | `${TASK_ID}` подставляется в разрешённые поля |
| Заголовок ресурса | `Authorization: Bearer ${TOKEN}` | `TOKEN` задаётся в разделе секретов |
| SQL-параметр | тип «Точное число», значение `${AMOUNT}` | После подстановки проверяется тип; в SQL используется `$1` |

Обычные переменные поддерживаются в пути, query, значениях заголовков/метаданных, строковых значениях JSON, текстовом теле и значениях SQL-параметров. JSON-числа не проходят через JavaScript `Number`. Подстановки в JSON сохраняют типы остальных значений; значение `${ID}` внутри JSON-строки остаётся строкой. В SQL-тексте `${NAME}` запрещено — используйте параметры `$1`, `$2`.

Неизвестное имя, цикл, отсутствующий ресурс и несовместимый тип останавливают подготовку до отправки прикладного запроса. Переменные процесса Windows из блока не читаются. Секреты разрешены в заголовках, метаданных и подключении; URL, query, тело и SQL-параметры используют открытые переменные.

При создании окружения задаются только имя и необязательное описание. Открытые и секретные переменные добавляются, переименовываются и удаляются через «Настроить переменные» на его странице рядом с ресурсами. Секретные значения после сохранения не возвращаются в форму: доступны оставить, заменить или явно удалить. Для переименования секрета задайте новое значение. Изменение имени/описания окружения не меняет переменные. Активный прогон продолжает использовать прежние версии настроек.

TLS включён по умолчанию в форме ресурса: он проверяет сервер. Для mTLS выберите отдельный режим, задайте CA при необходимости, клиентский сертификат PEM и секрет `PRIVATE_KEY`. При необходимости можно указать имя сервера TLS. Для незашифрованного локального стенда выберите plaintext явно. Сохранённый ключ остаётся при переходе в TLS/plaintext, но не включает клиентскую аутентификацию и удаляется только явно. Старые ресурсы и снимки с режимом TLS и клиентской парой продолжают работать как mTLS; форма распознаёт их. Несовместимая пара не сохраняется. Для PostgreSQL пароль задаётся секретом `PASSWORD`.

## Заголовок из HTTP-запроса

В заголовках HTTP-блока, gRPC-метаданных или общих заголовках ресурса переключите способ значения на «Из HTTP-запроса». Заполните метод, полный URL, query, обычные заголовки и необязательное тело. Например: POST `https://auth.local/token`, JSON `{"client_secret":"${CLIENT_SECRET}"}`, поле JSON `/data/access_token`, префикс `Bearer ` с пробелом в конце. Вложенные HTTP-источники в заголовках самого источника не поддерживаются.

Поле JSON использует JSON Pointer: `/tokens/0/value` — первое значение массива; `~1` означает `/` в имени, `~0` — `~`. Пустой указатель выбирает корень. Можно взять строку, число без округления или boolean. Отсутствующее поле, null, объект, массив, повреждённый/усечённый JSON или перенос строки в значении дают ошибку источника, основной запрос не запускается.

Выберите, когда получать значение:

- «Перед каждым вызовом» — новое значение для каждой новой попытки.
- «Один раз на прогон» — первое успешное значение этой настройки используется другими блоками того же прогона. Обновление страницы его не сбрасывает. Другой прогон получает новое значение; ошибка не кэшируется.

Пробный запуск редактора всегда получает отдельное значение. Сохранение и открытие настроек, создание прогона и повтор доставки одной команды запрос источника не выполняют. Заголовок блока переопределяет общий заголовок с тем же именем без учёта регистра.

TLS/mTLS источника настраивается независимо от основного ресурса. Для его ключа укажите имя сохранённого секрета, например `AUTH_PRIVATE_KEY`; сертификат может отличаться от сертификата основного сервиса. Обычные переменные допустимы в пути URL и query. Ссылки на секреты разрешены только в заголовках и теле источника. Хост задаётся в абсолютном URL явно.

Получение использует общий тайм-аут и отмену вызова, предел ответа 5 MiB, без переходов по redirect и автоматических повторов. При отказе видны этап источника, безопасная причина и отметка, что основной запрос не запускался. Полученное значение и префикс скрываются в отражённом ответе, различиях и истории; ответ источника не сохраняется.

У сохранённого секрета доступны действия «Оставить», «Задать новое значение» и «Удалить». Пустое новое значение отличается от удаления. После сохранения прежнее значение не передаётся браузеру. Известные секреты маскируются в ответах, ошибках и различиях после сравнения. Не вставляйте секреты напрямую в открытые поля сценария.

## Протоколы и ожидания

- HTTP: метод, относительный путь, отдельные query/headers, JSON или текст. Проверяются статус, указанные ожидаемые заголовки и выбранный формат тела. Ответ 404 можно ожидать как обычный результат. Redirect возвращается исходным ответом; переход по нему не выполняется.
- gRPC: полное имя сервиса, unary-метод, JSON сообщения и метаданные. Используется reflection сервера либо загруженный `.proto` bundle с относительными импортами. Ограничение bundle: 100 файлов, 5 MiB. Локальные файлы по путям из proto не читаются. Streaming не поддерживается. Ожидаемый `NOT_FOUND` может совпасть; для ошибки без сообщения выберите проверку только кода.
- PostgreSQL: отдельное целевое подключение, SQL с параметрами, режим «Строки» или «Команда». Выполняется один statement. `exec` сравнивает число затронутых строк. Режим строк сравнивает имена и PostgreSQL-типы колонок, порядок строк и типизированные ячейки. Для стабильного порядка используйте `ORDER BY`. `NULL`, пустая строка и JSON `null` различаются. Для чисел используйте «Целое»/«Точное число», для bytes — base64, для времени — RFC3339 с зоной.

JSON сравнивается структурно: порядок ключей объекта не важен, порядок массива и типы значений важны. Большие целые и decimal не округляются. В тексте CRLF приводится к LF. Ответы и различия показываются текстом; HTML из ответа не исполняется. В истории ожидание берётся из выполненной версии сценария.

Предел ответа — 5 MiB, SQL — дополнительно 1000 строк; список различий — 100 элементов. Тайм-аут по умолчанию 30 секунд, допустимо 1–300. Усечение, ошибка, отмена и тайм-аут дают «Не сравнено». Одновременно выполняется до четырёх вызовов, внутри прогона — один. Внешние запросы автоматически не повторяются.

## Ручное прохождение и история

«Начать прогон» фиксирует сценарий, окружение и версии ресурсов. Их последующее редактирование не меняет этот прогон. Вызовы запускаются кнопками; каждый запуск создаёт отдельную попытку. Предыдущие попытки доступны в подробностях, итог блока определяется последней попыткой.

Рядом доступно «Выполнить всё»: из редактора оно создаёт прогон и очередь атомарно; в открытом прогоне повторно выполняет все исходные вызовы в порядке шагов и блоков. Ручные шаги без вызовов пропускаются очередью. Ошибки, несовпадения и тайм-ауты не останавливают последующие вызовы. Счётчик сверху показывает обработанные блоки и проблемы; завершение очереди не завершает прогон и не выставляет ручные отметки. Обновление страницы не создаёт новую очередь.

Три ручных статуса находятся справа от заголовка шага: серый круг «Не проверен», зелёная галочка «Пройден», красный крестик «Не пройден». Исторические blocked/skipped отображаются как «Не проверен» с прежним значением рядом; сохранённые старые записи и итоги не переписываются.

«+ Вариант» создаёт исследовательскую вкладку у исходного вызова. Можно менять запрос и тайм-аут, сохранять незавершённый ввод и выполнять сохранённую версию. Ресурс, протокол и ожидание наследуются. Конфликт revision сохраняет введённый текст в форме. Вариантов не больше 20 на блок; все версии и попытки видны в истории. Они не заменяют исходный результат и не влияют на официальный итог. «Выполнить всё» их автоматически не запускает.

Верхняя «Отменить прогон» доступна во время вызова, включая получение заголовка. Подтверждённая отмена останавливает очередь и активные исходные/исследовательские попытки; сохранённые данные остаются. Ошибка записи отмены не считается успехом. Внешнее действие могло уже выполниться; отмена не откатывает целевую систему. После остановки процесса очереди, вызовы и прогон становятся interrupted без автоматического продолжения.

«Экспорт результата» есть у текущего прогона и истории. PDF скачивается готовым файлом; текст и Markdown копируются с возможностью ручного выделения при отказе clipboard. Оформленный текст вставляется в Word/почту с вызовами в виде встроенных PNG-частей. Описания и комментарии остаются редактируемым текстом. Экспорт не отправляет письма. В Windows используется системный RTF/HTML/Unicode clipboard; в других окружениях — browser HTML clipboard при его поддержке, иначе выводится явное сообщение.

Переключатель «Включать ожидаемые результаты» включён по умолчанию и применяется к текстам, полям сравнения и изображениям до построения документа. Все форматы используют один подготовленный сохранённый срез; новые результаты не дописываются в него. Текущий прогон помечается частичным. Для обновления есть «Подготовить заново». Native rich copy требует тот же срез: срок 10 минут, до 16 срезов / 64 MiB в памяти; перезапуск или вытеснение требуют новой подготовки. Пакет PNG ограничен 32 MiB, превышение показывается ошибкой без обрезания данных.

Выставьте ручной статус каждого шага и сохраните комментарии. Успешный вызов сам не выставляет статус шага. Прогон проходит, когда каждый ручной шаг отмечен «Пройден» и последняя попытка каждого вызова полностью совпадает. Ручная неудача или различие дают «Не пройден»; незавершённость, пропуск и неполный вызов — «Заблокирован». С активным вызовом завершение недоступно.

Первый завершённый прогон сохраняется автоматически с причиной «Первый прогон». Первый успешный — с причиной «Первый успешный». Один прогон может иметь обе причины. Они относятся ко всей жизни кейса, включая новые версии и архив. Любой другой завершённый прогон можно сохранить кнопкой; причина — «Сохранён вручную».

Все прогоны записываются в PostgreSQL сразу. «Сохранённые» — закреплённая история; остальные остаются на вкладке «Несохранённые» до явного удаления. Автоматической очистки нет. Сохранённый прогон удалить нельзя. Пробные вызовы редактора не создают прогон и не занимают первый результат.

После обновления страницы текущий прогон можно открыть на вкладке «Прогон». После потери Go-процесса незавершённые прогоны и попытки становятся `interrupted`; сохранённые шаги остаются. Отмена или обрыв связи не откатывают внешнюю систему: действие могло выполниться. Приложение не повторяет его при запуске; перед новой попыткой проверьте целевую систему.

## Изолированный стенд разработки

Для обычного знакомства используйте встроенный пример. `scripts/test-e2e.ps1` создаёт уникальные app/demo/target-схемы в общей БД `qag`, ограниченные роли и локальные HTTP/gRPC-цели. Chromium использует отдельный бинарник и собственные порты; очистка затрагивает только объекты текущего fixture. Помимо встроенного кейса, сценарий создаёт пользовательские ресурсы и блоки:

1. `AI_GW_SERVISE/task` → HTTP 200 и JSON `{"ok":true,"number":9007199254740993123,"token":""}`.
2. `grpc.health.v1.Health/Check`, сообщение `{}` → `OK`, `{"status":"SERVING"}`.
3. `SELECT $1::numeric AS amount`, параметр decimal `9007199254740993123.125` → колонка `amount` типа `numeric` и точное значение.
