# test-case-jira-export Specification

## Purpose

Экспорт определения кейса в Jira wiki markup позволяет вставить согласованный сценарий в комментарий Jira без запуска теста, создания истории и подключения qag к Jira.

## Requirements

### Requirement: Экспорт только определения сценария

UI и MCP SHALL экспортировать сохранённую версию тест-кейса в Jira wiki markup независимо от наличия прогонов. Экспорт SHALL включать имя, шаги и блоки в авторском порядке, заголовки, описания, протокол/имя ресурса и параметры исходных запросов. Фактические результаты, статусы/комментарии/даты прогона и исследовательские попытки MUST отсутствовать. Черновик SHALL экспортироваться без требования исполнимости; экспорт MUST не создавать или изменять кейс, прогон либо попытку.

#### Scenario: Кейс без истории
- **WHEN** пользователь экспортирует сохранённый кейс, который ещё не запускался
- **THEN** получает определение всех шагов и вызовов без фиктивного прогона или результатов

#### Scenario: Неполный черновик
- **WHEN** сохранённый кейс содержит незаполненный блок или шаг без заголовка
- **THEN** экспорт показывает имеющийся текст и понятные обозначения незаполненных данных без ошибки исполнения

### Requirement: Однозначный выбор версии и ожиданий

Экспорт SHALL проверять ожидаемую revision и выдавать один согласованный снимок определения. Устаревшая revision MUST давать конфликт без молчаливого экспорта другой версии. UI SHALL требовать явного сохранения либо выбора сохранённой версии при несохранённых правках. Переключатель includeExpected SHALL по умолчанию включать текстовые/типизированные ожидания шагов и блоков; выключение MUST исключать их целиком, включая подписи эталонов.

#### Scenario: Другой редактор изменил кейс
- **WHEN** клиент экспортирует revision, которая уже заменена
- **THEN** получает конфликт и может обновить кейс, а успешный файл с другой версией не выдаётся

#### Scenario: Ожидания выключены
- **WHEN** export вызван с includeExpected=false
- **THEN** остаются шаги и исходные запросы, без ожидаемых тел, кодов, таблиц и подписей изображений

### Requirement: Валидный wiki-текст и сохранение значимых данных

Выход SHALL быть UTF-8 текстом для Jira Wiki Style Renderer с читаемой нумерацией шагов и отдельными секциями запросов/ожиданий. JSON, SQL, многострочные строки, точные числа, NULL и пустая строка SHALL сохранять своё различие. Пользовательские спецсимволы и закрывающие code/noformat-маркеры MUST не разрушать структуру или превращать содержимое в дополнительные макросы. Формат MUST не подменяться Markdown либо ADF.

#### Scenario: Точный SQL и JSON
- **WHEN** кейс содержит numeric `9007199254740993123.125`, NULL, пустую строку и параметризованный SQL
- **THEN** wiki-текст сохраняет все цифры, типы и различия значений

#### Scenario: Специальные символы
- **WHEN** описание или тело содержит `{code}`, `{noformat}`, квадратные скобки, `|`, обратные слеши и строки с маркерами списков
- **THEN** они остаются содержимым сценария и не закрывают секции или создают постороннюю структуру комментария

### Requirement: Экспорт без внешних обращений и секретов подключений

Экспорт MUST не выполнять целевые запросы, HTTP-источники, получение proto по сети, подстановку сохранённых секретов либо обращения к Jira. `${NAME}` SHALL оставаться шаблоном; конфигурации подключений, секреты окружений/ресурсов и приватные ключи MUST не включаться. Значения литеральных Authorization, Proxy-Authorization, Cookie, Set-Cookie и X-Api-Key SHALL маскироваться без чтения значений секретов. Остальные открытые литералы SHALL передаваться как авторский текст. Для изображений ожиданий SHALL выводиться подпись/имя с пояснением ручного приложения; экспорт MUST не создавать локальные URL или ложные ссылки на вложения Jira.

#### Scenario: Недоступные сервисы
- **WHEN** кейс с HTTP/gRPC/SQL и динамическими переменными экспортируется при недоступных сервисах
- **THEN** экспорт успешен без сетевых действий, получения токенов и раскрытия настроек ресурсов

#### Scenario: Эталон требует вложения
- **WHEN** в ожидании есть изображение
- **THEN** текст объясняет его назначение и ручное приложение, не обещая загрузку в Jira

### Requirement: Копирование в UI и артефакт MCP

Редактор SHALL предоставлять явное действие копирования сценария для Jira с preview и выбором includeExpected. MCP SHALL предоставлять типизированный экспорт по ID/revision с теми же данными и UTF-8 артефактом, доступным по прежним правилам TTL, chunk и SHA-256. Экспорт MUST не публиковать комментарий или менять системный clipboard клиента неявно. Отказ browser clipboard SHALL показываться честно с доступным текстом для ручного копирования.

#### Scenario: Одинаковый экспорт двух интерфейсов
- **WHEN** UI и MCP экспортируют один ID/revision с одинаковым includeExpected
- **THEN** получают побайтово одинаковый wiki-текст, включая Unicode и экранирование

#### Scenario: Clipboard недоступен
- **WHEN** браузер отказывает в копировании
- **THEN** интерфейс не показывает ложный успех и оставляет подготовленный текст доступным
