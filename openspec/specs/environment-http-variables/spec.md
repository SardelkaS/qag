# environment-http-variables Specification

## Purpose

HTTP-переменные окружения позволяют один раз настроить получение общего значения для нескольких ресурсов и протоколов, сохраняя версии источника, изоляцию прогонов и маскирование результатов.

## Requirements

### Requirement: Определения HTTP-переменных окружения

Окружение SHALL поддерживать именованные HTTP-переменные наряду с прежними открытыми строковыми переменными и сохранёнными секретами. HTTP-определение SHALL содержать метод, абсолютный HTTP(S) URL, query, обычные заголовки, необязательное текстовое/JSON/form-urlencoded тело, отдельные TLS/mTLS, ссылку на секрет ключа, JSON Pointer, необязательные префикс/суффикс и режим `per_attempt` либо `per_run`. UI, API и MCP SHALL сохранять определение в версии окружения без выполнения HTTP-запроса. Новые строки с пустым именем SHALL пропускаться до проверки источника. Системное окружение MUST оставаться read-only.

Прежнее поле строковых переменных SHALL сохранять формат. API/MCP SHALL предоставлять отдельный набор `httpVariables`: отсутствие поля при обновлении сохраняет существующие HTTP-определения, явно пустой объект удаляет их; `null` MUST отклоняться. Метаданные окружения MUST сохранять оба набора и секреты без изменения определений.

#### Scenario: Общий токен
- **WHEN** пользователь сохраняет TOKEN_HTTP с POST-источником и JSON Pointer `/access_token` в окружении
- **THEN** определение доступно после повторного открытия, ни источник, ни целевые сервисы при сохранении не вызываются

#### Scenario: Пустая строка источника
- **WHEN** рядом с правильной переменной есть новая строка с пробельным именем и незаполненным источником
- **THEN** сохраняется только именованная переменная без ошибки пустого источника

#### Scenario: Системное окружение
- **WHEN** UI, API либо MCP пытается добавить HTTP-переменную встроенному окружению
- **THEN** действие отклоняется без записи и сетевых обращений

#### Scenario: Прежняя команда переменных
- **WHEN** клиент изменяет строки и секреты без поля `httpVariables`
- **THEN** существующие HTTP-определения окружения сохраняются

#### Scenario: Явное удаление либо неверный null
- **WHEN** клиент передаёт пустой объект `httpVariables` либо `null`
- **THEN** пустой объект очищает набор одной версией, а `null` отклоняется без изменения состояния

### Requirement: Общая область доступности и независимый источник

HTTP-переменная окружения SHALL подставляться как `${NAME}` в поддерживаемые HTTP path/query/headers/body, gRPC metadata/body и связанные SQL-параметры любого ресурса этого окружения. Правила кодирования, точности типов и запрета изменения адреса подключения, TLS или ожиданий SHALL совпадать с resource-http-variables. Совпадение имени со статической переменной, секретом либо переменной ресурса в том же контексте MUST отклоняться при сохранении соответствующей настройки и проверяться до сети. Источник окружения SHALL использовать только статические переменные и секреты своего окружения и собственные настройки HTTP/TLS. Он MUST не наследовать заголовки, переменные или секреты выбранного ресурса. Прямые и транзитивные зависимости от HTTP-переменных любого уровня MUST отклоняться до сети.

#### Scenario: Три протокола
- **WHEN** HTTP-, gRPC- и PostgreSQL-блоки разных ресурсов одного окружения используют `${TOKEN_HTTP}` в разрешённых параметрах
- **THEN** они получают значение общего определения с корректным кодированием, а SQL использует связанный параметр

#### Scenario: Конфликт локального имени
- **WHEN** ресурс определяет TOKEN_HTTP и окружению пытаются добавить одноимённую HTTP-переменную либо ресурс сохраняется в окружении с таким именем
- **THEN** изменение отклоняется с конфликтом имени без записи части настроек

#### Scenario: Изоляция учётных данных
- **WHEN** два ресурса имеют собственные одноимённые секреты, а HTTP-источник окружения использует секрет окружения
- **THEN** запрос источника всегда использует секрет окружения независимо от ресурса основного вызова

#### Scenario: Цепочка HTTP-источников
- **WHEN** источник окружения прямо либо через статическую ссылку требует другую HTTP-переменную или секрет, существующий только у ресурса
- **THEN** настройка или подготовка завершается безопасной ошибкой до первого HTTP-запроса

### Requirement: Получение и кеш по версии окружения

Источник SHALL выполняться только при фактическом использовании переменной после устойчивой регистрации основной попытки. Повторные ссылки внутри попытки SHALL получать одно значение. В режиме `per_run` успешный результат SHALL переиспользоваться всеми ресурсами одного прогона по зафиксированной версии окружения и определению; `per_attempt` SHALL получать новое значение в каждой новой попытке. Кеш MUST различать окружения, версии, имена и прогоны, не смешиваясь с локальными переменными ресурса. Пробный вызов SHALL иметь собственную область одной попытки. Ненужные источники, просмотр конфигурации/истории и повтор ключа команды MUST не вызывать получение. Ошибка MUST не кешироваться как значение.

#### Scenario: Один токен для нескольких ресурсов
- **WHEN** два блока разных ресурсов одного прогона используют одну переменную окружения `per_run`
- **THEN** источник вызывается один раз, включая последовательную очередь шага или всего кейса

#### Scenario: Следующий прогон и пробный запуск
- **WHEN** начинается другой прогон либо отдельный пробный вызов с тем же определением
- **THEN** значение получается заново и не берётся из кеша предыдущего прогона

#### Scenario: Режим на каждую попытку
- **WHEN** блок с `per_attempt` запускается дважды с разными ключами, но первая команда также повторно доставляется с прежним ключом
- **THEN** источник вызывается два раза, повтор доставки не создаёт третьего обращения

### Requirement: Снимок определения и защита результата

Прогон SHALL фиксировать версию окружения, определения HTTP-переменных и контекст сохранённых секретов. Последующие правки MUST не менять их для активного прогона. Получение SHALL применять правила точного JSON-скаляра, лимита ответа 5 MiB и значения 64 KiB, общего тайм-аута/отмены и запрета redirects/автоповторов. Ошибка либо отмена источника MUST останавливать основной вызов; сбой хранения начала попытки MUST предотвращать оба запроса. Сырой скаляр и значение с префиксом/суффиксом, включая экранированные формы, SHALL маскироваться в обычных результатах и диагностике. Сырой ответ источника, открытые вычисленные значения и кеш MUST не сохраняться в PostgreSQL, YAML, секреты, публичные снимки, историю или экспорт. Диагностическая копия запроса/ответа после маскирования SHALL быть доступна и переносима по call-logs; небезопасное тело SHALL пропускаться с причиной. Явная проверка HTTP-переменной окружения SHALL показывать открытые скаляр и итог только временно по http-variable-probes, без их записи в устойчивое состояние. Восстановление после перезапуска MUST не возобновлять получение.

#### Scenario: Изменение окружения во время прогона
- **WHEN** источник и секрет окружения изменены после начала прогона
- **THEN** старый прогон использует прежнюю версию, новый — новую; редактирование имени/описания не удаляет HTTP-определения

#### Scenario: Отражение значения
- **WHEN** целевой HTTP/gRPC/SQL возвращает исходный токен или полное значение с текстом до и после
- **THEN** UI, MCP, сохранённая попытка и отчёт маскируют обе формы без раскрытия сырого ответа источника; журнал показывает только маскированную диагностическую копию

#### Scenario: Отмена либо отказ записи
- **WHEN** регистрация попытки не подтверждена либо источник отменён в ходе получения
- **THEN** основной запрос не начинается, при неподтверждённой регистрации источник также не вызывается, а перезапуск не возобновляет сеть

#### Scenario: Проверка без выбранного ресурса
- **WHEN** пользователь проверяет HTTP-переменную окружения и получает скаляр
- **THEN** непосредственный результат показывает значение, а журнал и файл состояния не содержат его открытой копии
