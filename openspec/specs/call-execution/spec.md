# call-execution Specification

## Purpose

Выполнение блоков позволяет вручную инициировать реальные HTTP-, gRPC- и PostgreSQL-запросы из сценария и получать ограниченный по времени, воспроизводимый результат на Go-сервере.

## Requirements

### Requirement: Явный запуск блока и состояние выполнения

Каждый блок SHALL иметь собственную кнопку запуска в редакторе и в прогоне. Сервер SHALL выполнять сохранённый блок с выбранным окружением и возвращать идентификатор попытки, состояние, время начала, длительность и результат. UI MUST различать ожидание, выполнение, полученный ответ, ошибку, тайм-аут и отмену. Повторная доставка одной команды запуска MUST не создавать второе выполнение; новая осознанная попытка SHALL получать новый идентификатор. Автоматические повторы запросов MUST быть выключены.

#### Scenario: Двойное нажатие кнопки запуска
- **WHEN** один и тот же запуск повторно доставлен серверу, пока попытка выполняется
- **THEN** сервер возвращает ту же попытку, а целевой сервис получает не более одного вызова от этой команды

#### Scenario: Повторная проверка пользователем
- **WHEN** завершившуюся попытку пользователь явно запускает заново
- **THEN** создаётся новая попытка с отдельным результатом, а предыдущая сохраняется в составе прогона

### Requirement: Выполнение HTTP-запросов

HTTP-блок SHALL поддерживать метод, путь относительно именованного ресурса, query-параметры, заголовки и текстовое либо JSON-тело. Сервер MUST применять параметры ресурса и TLS перед отправкой и показывать фактический HTTP-статус, заголовки и тело ответа. HTTP-ответ с кодом 4xx или 5xx SHALL считаться полученным ответом для сравнения с ожиданием, а не автоматически транспортной ошибкой. Перенаправление на другой адрес MUST не выполняться автоматически.

#### Scenario: Ожидаемый отрицательный HTTP-ответ
- **WHEN** запрос возвращает 404, а блок ожидает статус 404 и соответствующее тело
- **THEN** ответ доступен для сравнения и может получить результат «Совпадает»

#### Scenario: Редирект
- **WHEN** ресурс отвечает статусом 302 с `Location` на другом хосте
- **THEN** приложение показывает исходный ответ 302 и не пересылает запрос и секреты на указанный хост

### Requirement: Выполнение unary gRPC

gRPC-блок SHALL задавать полное имя сервиса и метода, JSON-сообщение запроса, метаданные и ожидаемый gRPC-код. Приложение SHALL получать описание сообщения через server reflection либо загруженный набор `.proto` со всеми импортами. Результат SHALL включать gRPC-код, сообщение статуса, ответ в JSON, начальные метаданные и trailers при их наличии. Streaming-метод и недоступное описание MUST приводить к явной ошибке до вызова прикладного метода.

#### Scenario: Сервер без reflection
- **WHEN** reflection недоступен, но для ресурса загружены корректные `.proto` со всеми импортами
- **THEN** unary-запрос выполняется по загруженному описанию и результат отображается в JSON

#### Scenario: Неожиданный streaming-метод
- **WHEN** пользователь выбирает метод с потоком сообщений
- **THEN** приложение показывает, что первая версия поддерживает только unary, и не запускает метод

#### Scenario: Ожидаемый gRPC-статус ошибки
- **WHEN** сервер возвращает `NOT_FOUND`, а этот код указан в ожидании
- **THEN** код участвует в обычном сравнении, а отсутствие сообщения ответа не подменяется сетевой ошибкой

### Requirement: SQL-вызовы PostgreSQL с параметрами

SQL-блок SHALL выбирать PostgreSQL-ресурс, SQL-текст, упорядоченные типизированные параметры `$1`, `$2` и режим результата «Строки» либо «Команда». Значения MUST передаваться средствами параметризации PostgreSQL без конкатенации в SQL. Режим «Строки» SHALL показывать колонки и строки, режим «Команда» — число затронутых строк. SQL-ошибки SHALL показывать код и безопасное описание. Произвольные переменные MUST не подставляться в SQL-текст; допустима подстановка в значения параметров. Приложение MUST не обещать отмену уже совершённых изменений при тайм-ауте или потере связи.

#### Scenario: Кавычки в параметре
- **WHEN** значение параметра содержит кавычки и SQL-подобный текст
- **THEN** значение передаётся как данные одного параметра, не меняя структуру запроса

#### Scenario: Записывающая команда
- **WHEN** пользователь запускает допустимый `UPDATE` в режиме «Команда»
- **THEN** команда выполняется с правами выбранного ресурса и показывает число затронутых строк

#### Scenario: Ошибка SQL
- **WHEN** запрос содержит ошибку или у пользователя БД нет необходимых прав
- **THEN** блок показывает ошибку PostgreSQL, а приложение не выполняет запрос повторно автоматически

### Requirement: Тайм-ауты, отмена и ограничение результата

Вызов SHALL иметь настраиваемый тайм-аут, по умолчанию 30 секунд и не более 300 секунд. Пользователь SHALL иметь возможность отменить выполняющуюся попытку. Приложение MUST ограничивать захватываемый ответ 5 MiB, а SQL-выборку — также 1000 строками, и MUST явно обозначать превышение лимита. Тайм-аут, отмена и усечение MUST не отображаться как полное успешное совпадение. После отмены интерфейс SHALL пояснять, что запрос мог уже повлиять на внешнюю систему.

#### Scenario: Превышение времени
- **WHEN** целевой сервис не завершил ответ до установленного тайм-аута
- **THEN** попытка переходит в состояние тайм-аута и пользователь получает управление без автоматического повтора

#### Scenario: Большая SQL-выборка
- **WHEN** запрос возвращает более 1000 строк
- **THEN** приложение показывает ограниченный результат с признаком усечения и не объявляет его полным совпадением

### Requirement: Связь результата с конкретной попыткой

Результат SHALL содержать протокол, версию блока, окружение и обезличенные сведения о разрешённом ресурсе. Поздний результат другой попытки MUST не подменять выбранный результат. Во время прогона все попытки SHALL привязываться к его снимку, а сравнение SHALL выполняться с ожиданием из этого снимка. Выполнение блока из редактора MUST не создавать самостоятельный прогон тест-кейса.

#### Scenario: Изменение ожидания после старой попытки
- **WHEN** пользователь изменил ожидание в редакторе после получения результата
- **THEN** старый результат помечается как относящийся к прежней версии и не сравнивается молча с новым ожиданием

#### Scenario: Пробный запуск в редакторе
- **WHEN** пользователь запускает блок без начала прогона
- **THEN** интерфейс показывает результат для проверки блока, а признаки первого и первого успешного прогона тест-кейса не изменяются
