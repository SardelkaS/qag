## MODIFIED Requirements

### Requirement: Локальный Web UI на Go и TypeScript

Приложение SHALL предоставлять браузерный UI на TypeScript и сервер на Go без формы входа для одного пользователя. Готовая сборка SHALL обслуживать UI, API и включённый по умолчанию MCP одним Go-процессом на общем HTTP-адресе. Нативный режим MUST слушать только loopback-интерфейс. Явно выбранный контейнерный режим SHALL разрешать listener, доступный перенаправлению Docker, при публикации HTTP только на loopback хоста в штатном Compose. Исполнение целевых HTTP-, gRPC- и SQL-вызовов SHALL происходить на сервере. Изменяющие состояние и исполняющие команды браузерного API MUST не приниматься из постороннего веб-источника; настройка контейнерного режима MUST не отключать его проверку Host и Origin. Браузерный API MUST сохранять CSRF-защиту, а MCP SHALL быть доступен без авторизации, браузерной сессии и ограничений Host/Origin/cross-site. Оба канала SHALL использовать один жизненный цикл и те же данные без второго владельца пространства БД.

#### Scenario: Запуск и открытие UI
- **WHEN** пользователь запускает настроенное приложение и открывает его локальный адрес
- **THEN** появляется каталог тест-кейсов без страницы входа и доступен выбор раздела ресурсов

#### Scenario: Команда с постороннего сайта
- **WHEN** другая веб-страница пытается отправить команду запуска через браузерный API локального сервера приложения
- **THEN** сервер отклоняет её до выполнения внешнего запроса

#### Scenario: Контейнерный и нативный listener
- **WHEN** приложение настроено слушать все контейнерные интерфейсы
- **THEN** запуск разрешён только при явном контейнерном режиме, а нативная конфигурация по умолчанию сохраняет запрет такого listener

#### Scenario: Одновременная работа UI и MCP
- **WHEN** настроенный MCP-клиент сохраняет сценарий и пользователь открывает его в UI
- **THEN** оба канала видят те же данные, а подключение MCP не запускает повторное восстановление прогонов

#### Scenario: Раздельная защита команд
- **WHEN** MCP обращается без авторизации, а запрос к браузерному API не содержит CSRF
- **THEN** MCP-команда доступна, но изменяющая браузерная команда отклоняется по прежним правилам

### Requirement: Инструкция локального развёртывания

Репозиторий SHALL содержать воспроизводимые инструкции сборки Go/TypeScript с иконкой, запуска одной PostgreSQL, подготовки изолированных тестовых схем/ролей, настройки подключения и ключа секретов, запуска приложения и выполнения проверок. README SHALL начинаться с актуального контейнерного запуска приложения и БД через Docker Compose, отдельно описывать эквивалентный запуск через Makefile и доступный адрес браузера. Для контейнерного пути SHALL быть достаточны Docker и Compose; GNU Make SHALL требоваться только для Make-варианта. Документация SHALL объяснять смену опубликованного порта, сохранение данных и ключа, импорт прежней установки и адреса ресурсов хоста при выполнении запросов из контейнера. Нативный Windows-режим SHALL оставаться описанным для разработки; его команды MUST работать в PowerShell. Документация SHALL описывать backup PostgreSQL и отдельного ключа/конфигурации, переход со старого тестового контейнера без удаления рабочего тома, ограничения локального режима и отсутствие гарантии отката внешнего действия при отмене. Платформенные возможности экспорта SHALL описываться согласно фактическому backend: Linux использует browser HTML clipboard, native Windows clipboard относится к нативному Windows-запуску. README SHALL описывать автоматическое включение MCP без токена, адрес /mcp на обычном и изменённом порту, совместимые протоколы, подключение без Authorization, каталог инструментов и полный пример от встроенного кейса до отчёта. Инструкция SHALL различать серверные файлы и clipboard клиента, объяснять revision, idempotencyKey, истечение артефактов и ограничения локального доступа без публикации реальных секретов.

#### Scenario: Настройка на чистой машине
- **WHEN** разработчик следует инструкции с установленными указанными инструментами и чистой PostgreSQL-БД
- **THEN** он собирает контейнерный образ, запускает UI и проходит демонстрационный ручной тест-кейс с локальными тестовыми ресурсами

#### Scenario: Проверки на общей БД
- **WHEN** разработчик выполняет документированные проверки рядом с рабочим приложением
- **THEN** используется один PostgreSQL-контейнер, тестовые объекты изолированы схемами и рабочие данные сохраняются

#### Scenario: Два способа контейнерного запуска
- **WHEN** пользователь выбирает в README прямой Docker Compose либо вариант с GNU Make
- **THEN** оба варианта приводят к одному адресу Web UI и одному сохраняемому состоянию без требования установить Go или Node.js на хост

#### Scenario: Подключение MCP по README
- **WHEN** пользователь следует MCP-разделу README для штатного Compose либо нативной разработки
- **THEN** клиент подключается по документированному адресу, получает инструменты и проходит встроенный пример с готовым отчётом без обязательного браузера
