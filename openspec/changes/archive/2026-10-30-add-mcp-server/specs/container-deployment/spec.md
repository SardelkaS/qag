## MODIFIED Requirements

### Requirement: Опубликованный локальный HTTP-порт

Compose SHALL публиковать HTTP-порт приложения на `127.0.0.1:8080` по умолчанию и позволять явно выбрать другой свободный порт хоста. Из браузера SHALL быть доступны UI, API и встроенный демонстрационный HTTP через этот опубликованный адрес. Контейнерный listener SHALL быть доступен перенаправлению Docker, а внутренний порт SHALL оставаться независимым от опубликованного. Проверки Host и Origin для UI/API, а для браузерного API также CSRF, MUST учитывать выбранный адрес и MUST не заменяться wildcard-разрешением либо доверием произвольным forwarded-заголовкам. Штатное отображение портов MUST не открывать приложение на всех интерфейсах хоста; демонстрационный gRPC MUST не требовать публикации отдельного порта. MCP SHALL по умолчанию быть доступен по /mcp на том же опубликованном адресе без отдельного порта, контейнера или публикации на сетевых интерфейсах хоста.

#### Scenario: Доступ из браузера
- **WHEN** Compose сообщает готовность установки с настройками по умолчанию
- **THEN** `http://127.0.0.1:8080` открывает приложение, а действия сохранения и запуска проходят обычную проверку локальной сессии

#### Scenario: Другой порт хоста
- **WHEN** пользователь задаёт внешний HTTP-порт 18088
- **THEN** UI и изменяющие API-команды работают через `http://127.0.0.1:18088` без правки кода и без отключения проверки Origin

#### Scenario: Посторонний источник
- **WHEN** запрос к браузерному API опубликованного приложения имеет посторонний Host, Origin либо неверный CSRF-токен
- **THEN** сервер отклоняет его до изменения данных или внешнего вызова

#### Scenario: MCP на изменённом порту
- **WHEN** установка с включённым MCP опубликована на 127.0.0.1:18088
- **THEN** MCP-клиент использует http://127.0.0.1:18088/mcp без токена, а UI и прежняя защита продолжают работать

## ADDED Requirements

### Requirement: MCP включён в штатном контейнере

Штатный контейнер SHALL включать MCP автоматически без токена и настройки авторизации. Подключение MCP и формирование всех отчётов MUST не требовать Node.js, браузера, Go или PowerShell на хосте и MUST не создавать второй PostgreSQL. Пересоздание на прежних томах SHALL сохранять исходный мастер-ключ, БД и историю; MCP SHALL оставаться доступным без повторной настройки доступа.

#### Scenario: Прежняя установка
- **WHEN** пользователь обновляет и запускает существующую установку без новой настройки
- **THEN** UI, БД и открытый MCP становятся готовы с прежними данными

#### Scenario: Пересоздание
- **WHEN** пользователь пересоздаёт штатный контейнер
- **THEN** MCP доступен на прежнем HTTP-порту без Authorization, а все существующие данные сохранены

#### Scenario: Старый параметр токена
- **WHEN** в приватной конфигурации или среде сохранился QAG_MCP_TOKEN
- **THEN** приложение игнорирует его и предоставляет открытый MCP
