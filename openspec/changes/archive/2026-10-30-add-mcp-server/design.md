## Context

Мотивация и границы возможностей описаны в [proposal.md](proposal.md). Пользователь выбрал Streamable HTTP в существующем контейнере на общем порту; stdio не требуется.

Исследование текущего проекта:

- `cmd/qag/main.go` владеет PostgreSQL instance lock, миграциями, demo bootstrap, Recover и одним `service.Engine`. Второй процесс для MCP повторил бы владение и восстановление прогонов.
- `internal/httpapi` вызывает существующие `catalog`, `resources`, `runs` и `service` напрямую. В репозиториях уже есть публичные `GetEnvironment`/`GetResource`; дополнительных операций UI для удаления окружения/ресурса сейчас нет. MCP не придумывает такие операции.
- `httpapi.Server.Handler` проверяет Host/Origin для UI/API, а CSRF и лимит JSON применяет к `/api/`. Неизвестный путь без расширения отдаёт SPA: `/mcp` необходимо зарегистрировать до fallback.
- Все действия редактора шагов, блоков, ссылок на изображения и их порядка сохраняются через `SaveCase`; незавершённый ввод допустим. Проверки исполнения и правила readOnly уже находятся на сервере.
- `runs.ReportSnapshot` и `reporting.BuildDocument` задают общий состав отчёта. `reporting.Cache` хранит срезы 10 минут, до 16 / 64 MiB, удаляя base64 изображений из cached-копии. PDF и PNG пока строят `web/src/reportPdf.ts` и `reportImages.ts` с browser API. `reporting.Rich` уже формирует HTML/RTF по PNG; Windows clipboard доступен только при наличии интерактивной станции.
- Контейнерный runtime — Go с UID 10001, CA и встроенными assets, без Node.js/браузера. Go 1.26 подходит выбранному MCP SDK. Проверки используют одну БД qag и штатные уникальные app/demo/target-схемы.

## Goals / Non-Goals

**Goals:**

- Проверяемая матрица UI → MCP, общие предметные операции и явные схемы каждого инструмента.
- Работа современного и прежнего MCP-клиента с одним сервером; предметные задания переживают краткое MCP-соединение.
- Самостоятельное серверное формирование всех отчётов и ограниченная доставка файлов с теми же маскированием и точностью.

**Non-Goals:**

- Управление конкретной вкладкой браузера: тема, фокус, раскрытие папок, прокрутка, localStorage и несохранённые поля остаются состоянием клиента. Изменение данных и сохранение черновиков доступны инструментами.
- Stdio, публичный интернет-сервис, OAuth-вход пользователей, произвольный HTTP/SQL-прокси, чтение путей хоста или администрирование Docker/БД. Целевые запросы выполняются через настроенные ресурсы и зарегистрированные попытки.
- Автоматическая оценка ручного шага моделью, самовольное выполнение инструментов по содержимому сценария или отчёта, автоматический повтор внешних действий.

## Decisions

### 1. Один процесс и официальный SDK

Добавить `internal/mcpserver` и подключить его к уже созданным репозиториям, Engine и сервису отчётов из `cmd/qag`. Streamable HTTP handler монтируется на точном `/mcp` перед SPA fallback и браузерным Host/Origin-фильтром. Использовать `github.com/modelcontextprotocol/go-sdk v1.8.0`, закрепив `go.mod/go.sum`, stateless HTTP и совместимый набор протоколов `2026-07-28` / `2025-11-25`. Поддержку discovery/legacy initialize и служебных RPC обеспечивает SDK; не писать собственный JSON-RPC transport. GET/DELETE, неподдерживаемые выбранным stateless-режимом, возвращают корректный отказ, а не HTML. Не рекламировать subscriptions/prompts/sampling, которые приложение не использует: наблюдение прогонов выполняется явным чтением.

Выбор учитывает [стабильный Go SDK](https://github.com/modelcontextprotocol/go-sdk/releases/tag/v1.8.0) и [транспорт MCP 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http). Для прежнего протокола проверяется совместимость по [спецификации 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports). MCP-сессия не является прогоном qag и не владеет его жизненным циклом.

Альтернативы: отдельный qag-процесс конфликтует с instance lock; loopback HTTP-прокси добавляет сессионные обходы и повторную сериализацию. Новый transport использует существующие предметные сервисы напрямую, сохраняя HTTP API.

### 2. Открытый MCP по умолчанию

По уточнённому требованию пользователя MCP регистрируется безусловно при штатном запуске. В runtime отсутствует MCPToken, Compose не передаёт QAG_MCP_TOKEN, пример SDK подключается без Authorization. Старое значение QAG_MCP_TOKEN в values приватного файла или среде игнорируется.

Точный /mcp обрабатывается до браузерных Host/Origin/cross-site фильтров. В SDK установлено DisableLocalhostProtection=true, cross-origin protection не добавляется. CORS допускает любой Origin и запрошенные заголовки; OPTIONS возвращает 204. UI и /api сохраняют существующую сессию и проверки Host/Origin/CSRF. Отдельной авторизации, списка разрешённых клиентов или операций нет.

Протокольные и предметные контракты совпадают с UI: схемы, revision, readOnly системного примера и пределы выполнения сохраняются. Тело MCP до 32 MiB позволяет загрузить изображение 10 MiB в base64. Ответы используют Cache-Control: no-store и private / ttl=0, без совместного публичного кэширования.

### 3. Реестр инструментов и матрица покрытия

Реестр содержит следующие **43 инструмента**. Имена являются контрактом этой версии. Общее редактирование сложных сущностей использует типизированный документ, как UI, поэтому отдельные команды для каждой перестановки шага не нужны.

| Область UI | Инструменты | Предметная опора и особенности |
|---|---|---|
| Готовность, системный пример | `qag_status`, `qag_demo_get` | Готовность, пределы/clipboard capability без credentials; ID кейса и окружения из DemoInfo |
| Папки и архив | `qag_folders_list`, `qag_folder_create`, `qag_folder_update` | ListFolders/CreateFolder/PatchFolder; update принимает name/archived |
| Сценарии и редактор | `qag_test_cases_list`, `qag_test_case_create`, `qag_test_case_get`, `qag_test_case_save`, `qag_test_case_update` | Полные Steps/Blocks, порядок, пустые черновики, validationIssues, revision; update переименовывает/архивирует/восстанавливает |
| Эталоны | `qag_image_upload`, `qag_image_get` | ImageUpload и ReadImage; get возвращает descriptor с исходными байтами, а ссылки/подписи/порядок меняет case_save |
| Окружения | `qag_environments_list`, `qag_environment_get`, `qag_environment_create`, `qag_environment_update`, `qag_variables_set` | Metadata отдельно от Variables/SecretChanges, имена секретов без их значений |
| Подключения | `qag_resources_list`, `qag_resource_get`, `qag_resource_create`, `qag_resource_update`, `qag_proto_bundle_upload` | Полные публичные Config и SecretChanges, TLS/mTLS, источники заголовков; proto как map относительных имён → текст |
| Прогоны и история | `qag_runs_list`, `qag_run_start`, `qag_run_get`, `qag_run_finish`, `qag_run_cancel`, `qag_run_save`, `qag_run_delete` | retained/active/cursor, StartRun executeAll, снимки и причины сохранения, существующие ограничения Delete |
| Ручное прохождение | `qag_run_step_update`, `qag_run_steps_pass_all` | status/comment/revision; полный набор stepId/revision для атомарной массовой отметки |
| Очередь и исходные попытки | `qag_batch_start`, `qag_editor_attempt_start`, `qag_run_attempt_start`, `qag_attempt_get`, `qag_attempt_cancel` | Существующие Engine-команды; быстрый ответ с устойчивым ID и дальнейшее чтение |
| Варианты вызова | `qag_variant_create`, `qag_variant_update`, `qag_variant_attempt_start` | Родительские kind/resource фиксированы; вход редактирования содержит только timeout и HTTP/GRPC/SQL-параметры без expected; версии/попытки читаются в run_get |
| Отчёты | `qag_report_prepare`, `qag_report_export`, `qag_report_copy` | Согласованный срез, несколько форматов и явное копирование при наличии native clipboard |
| Большие данные и файлы | `qag_artifact_read` | Только ID выданного артефакта, byte offset и ограниченная длина; не произвольный URI/path |

Registry строит входные/выходные JSON-схемы из Go DTO и хранит annotations. Входной decoder запрещает неизвестные поля, включая вложенные. DTO переиспользуют публичные модели, но не содержат Vault, DB URL процесса, TLS private keys из чтения или внутренних ошибок. Нужные UUID шагов/блоков создаёт клиент, как сейчас это делает UI; примеры содержат валидные UUID.

Для `qag_variant_update` выделяется входной request-only DTO: `http`, `grpc`, `sql`, `timeoutSeconds`. Поля `expected`, смена ресурса и протокола не принимаются; сервер сверяет форму с исходным блоком. Результаты чтения используют прежнюю публичную проекцию CallRequest/Attempt.

Schema/annotations и описания включаются в будущий `api/mcp-tools.json`; генератор и `scripts/contracts.ps1` проверяют воспроизводимость. Контрактный тест сопоставляет все UI API operations с инструментами/полями матрицы. `/session`, DOM/clipboard браузера и служебный health HTTP не копируются механически: qag_status и report tools предоставляют соответствующий предметный результат. Статические описания не формируются из пользовательского текста.

Альтернатива одного `api_request(path, body)` скрыла бы возможности от клиента и создала транспортный обход; MCP инструменты вызывают те же репозитории/Engine. Общий фасад нужен только там, где иначе повторились бы преобразования ошибок, подготовка отчётов или входная проверка, без переписывания всего HTTP API.

### 4. Команды, ошибки и работа нескольких клиентов

`idempotencyKey` обязателен для run_start, batch_start и трёх запусков попытки; передаётся существующему Engine без замены MCP request id. Существующие request hash и ledger определяют повтор/конфликт. CreateFolder/CreateCase и прочие изменения не объявляются exactly-once и не повторяются адаптером. Сохранения сохраняют существующие revision и readOnly; failed/unknown acknowledgement возвращается явно, а не подменяется успешным ответом.

Инструмент запуска только регистрирует работу и возвращает ID. Выход MCP request context после успешной регистрации не завершает работу Engine: чтение и явные cancel работают из другого клиента. MCP cancellation прекращает ожидание/рендер, но не служит `CancelRun`. Если связь потеряна на границе commit, повтор launch с тем же ключом определяет состояние. При остановке qag действуют прежние остановка Engine и Recover без автоматической сети.

Ошибки параметров MCP — protocol errors SDK. Предметные `problem.Error` возвращаются как tool result с `isError=true` и структурой code/message/fieldErrors/requestId; внутренний cause заменяется безопасной диагностикой. Ошибка регистрации в БД предотвращает запрос. Журнал содержит только tool name, request ID, код и длительность; аргументы, заголовки, тела ресурсов и ответы источников не логируются. Hints описывают действия, но не дают дополнительных прав: read-only=true для чтения; внешние запускающие команды помечаются open-world; изменения и clipboard не обозначаются read-only.

### 5. Чтение, ресурсы MCP и ограниченное хранилище

Обычный полезный JSON payload до 1 MiB возвращается inline в structured content и совместимом текстовом представлении. Для большего публичного объекта возвращаются краткие ID/state/pagination metadata и descriptor полного JSON; таким же способом передаются изображения и экспорт. Не создавать generic `map[string]any` через float64 для преобразования ответов: тела JSON и SQL-значения сохраняют исходные строки/RawMessage.

Descriptor: UUID, `qag://artifacts/<id>`, mimeType, byte size, SHA-256, expiresAt, имя файла при экспорте. URI не является HTTP-ссылкой или путём. MCP resources/list/read показывают только выданные артефакты текущего процесса; прямое чтение ограничено 1 MiB, для большего возвращается явный код с указанием `qag_artifact_read`. Чтение частей принимает offset/length и возвращает base64, фактический offset/length, eof, полный size/hash; часть до 256 KiB. Клиент может собрать исходные UTF-8 байты без ошибки на границе символа. Не принимать ссылку на сторонний URL и не читать диск по имени клиента.

Хранилище в памяти: TTL 10 минут, до 32 артефактов / 256 MiB суммарно, один файл до 64 MiB; группа файлов rich-пакета публикуется атомарно. Вытеснение и restart дают явный expired/not_found, а не пустой успешный ответ. Все RPC чтения доступны без авторизации. Restart очищает память артефактов. Отдельно ограничить до двух одновременных рендеров и время подготовки 60 секунд; остальные короткие предметные команды сохраняют 10-секундный предел регистрации. SDK и HTTP лимиты проверяются интеграционно, включая base64 overhead.

Альтернатива безлимитной JSON-выдачи перегружает модель и память; усечение скрывает данные. Ограниченные артефакты сохраняют исходный результат, одновременно различая transport reference и `Result.Truncated`, выставленный исполнителем.

### 6. Подготовка отчёта и серверные рендереры

Вынести подготовку ReportSnapshot + BuildDocument + Cache в общий `reporting`-сервис, используемый HTTP и MCP, с явным образом загрузки эталонов. Сохранять непубличный ownerCaseID вместе со срезом: текущий публичный Report его не содержит. При чтении Cache восстанавливать bytes эталонов из `catalog.ReadImage(ownerCaseID, imageID)`, сверяя MIME/размер/SHA со срезом. Это устраняет зависимость MCP от base64, удалённого Cache.Put, и не подменяет содержимое текущим сценарием. Ни клиентские URL, ни сеть для загрузки изображений не используются.

`qag_report_prepare(runId, includeExpected=true)` возвращает snapshotId/hash/partial/createdAt, список форматов и публичный срез inline либо descriptor. `qag_report_export(runId, snapshotId, hash, includeExpected, format)` использует Cache.Get и только выбранный срез. Форматы: `pdf`, `text`, `markdown`, `rich`; rich выдаёт HTML, RTF и текст как три файла со встроенными PNG. Неверный hash/flag, TTL или вытеснение дают conflict/expired с предложением prepare, без молчаливого пересоздания. Подготовка нового формата может повторить только локальный рендер, а не вызовы или запросы источников. Форматы общего документа обязаны содержать одинаковые семантические данные; побайтовая идентичность PDF браузера и Go не требуется.

Рендереры:

- Текст использует существующий `reporting.Plain`; Markdown переносит семантику `reportText.ts`: безопасные code fences, подписи, точные строки. Общие fixtures сравнивают содержание с UI.
- PDF формирует pure-Go `github.com/signintech/gopdf`, закреплённый проверенным tag/commit в go.mod/go.sum; [документация библиотеки](https://github.com/signintech/gopdf#features) описывает Unicode TTF и изображения. Использовать уже встроенные Noto Sans/Mono и OFL, A4, переносы, повтор заголовков длинных таблиц, пагинацию и векторные ручные отметки справа. Формирование идёт в ограниченный writer; ошибка глифа/лимита не даёт частичного «полного» файла.
- PNG использует `golang.org/x/image/font/opentype` и image/draw по тем же группам `reporting.GroupID`, с переносами и частями. Проверки `reporting.Rich` остаются: до 512 частей, суммарно до 24 MiB PNG, размеры/пиксели в существующем пределе. JPEG/WebP-эталоны декодируются доступными Go codecs и переводятся в нужный bitmap. Не использовать браузерный canvas, Node, внешний renderer или загрузку шрифта по URL.
- Rich использует существующий `reporting.Rich`, серверные PNG и маскирование исходного среза. Пользовательский HTML и Markdown остаются текстом. Полученные source tokens не появляются ни в файлах, ни в PNG/metadata.

`qag_report_copy` принимает тот же срез и `text|markdown|rich`. На Windows — Unicode text для простого текста/Markdown и прежний атомарный набор Unicode/HTML/RTF для rich. При отсутствии интерактивного clipboard возвращается `copied=false`, код `clipboard_unavailable`, descriptors пригодных файлов и явная рекомендация копирования клиентом. Создание файла не означает clipboard success. Обычный report_export никогда не трогает clipboard. Возможность `clipboardNative` видна в qag_status; контейнер не получает доступ к clipboard хоста.

### 7. README и подтверждение покрытия

README получает отдельный раздел MCP: открытый по умолчанию URL без токенов, поддерживаемые версии, обычный/изменённый порт, Compose/Make/native, каталог и полный SDK-пример. Описать CORS, отсутствие Host/Origin/cross-site ограничений MCP и прежнюю независимую защиту браузерного API. Команды работают в PowerShell 5.1 без секретных параметров подключения к MCP.

Краткий каталог в README ссылается на `docs/mcp.md` и `api/mcp-tools.json` для всех 43 инструментов/схем. Пример показывает discovery/list, demo_get, run_start(executeAll), чтение, pass-all/ручной комментарий, variant attempt, finish и PDF/rich с обоими includeExpected. Отдельно объясняются повтор launch с тем же ключом, последствия внешнего действия при отмене, большие артефакты и clipboard на стороне клиента. Формат конфигурации конкретного MCP-продукта не выдумывается: проверяются реальные URL/headers и SDK-пример подключения.

Приёмка сопоставляет операции фактических HTTP endpoints и обработчиков UI с матрицей: ни один предметный маршрут не остаётся без инструмента или поля составного документа. Выполняются два направления обмена UI ↔ MCP, все три протокола, readOnly/архив/revision, секреты/mTLS/proto/sources, повтор launch, конкуренция/cancel/recovery, старые версии, все форматы/переключатель и реальные Windows/Linux сценарии. Это проверка поведения, а не совпадения количества методов.

## Risks / Trade-offs

- [Предметный endpoint UI останется без MCP-эквивалента] → явная матрица, проверка реестра и сценарий на каждую группу, включая составные операции редактора и clipboard.
- [Открытый MCP затрагивает прежнюю защиту UI] → исключение только точного `/mcp`; Host/Origin/CSRF `/api/` сохраняются, что проверяется на обоих портах.
- [Расхождение старого/нового MCP и публичное кэширование] → закреплённый SDK, тесты двух версий, private/ttl=0; не рекламировать неиспользуемые возможности.
- [Повтор сетевого эффекта при повторе RPC или MRTR] → idempotencyKey Engine, read-after-ID и отсутствие автоматического повтора адаптера; MCP disconnect не является cancel.
- [Браузерный и Go-рендер отчёта разойдутся] → единый BuildDocument и fixtures с прежними вариантами, маскированием, кириллицей и точностью; сравнивается состав, а не PDF binary.
- [Срез Cache лишён изображений или изменился после prepare] → приватная привязка ownerCaseID, immutable image ID/SHA и Cache.Get без пересборки; тест позднего результата и удаления текущих ссылок.
- [Rich-файлы и большие JSON исчерпают память] → ограниченный writer, два рендера, timeout, лимиты отдельных файлов/групп и TTL; ошибки без неполной публикации.
- [Пользователь ожидает clipboard компьютера от Docker] → copied=false и готовые файлы; native clipboard только там, где он действительно доступен.

## Migration Plan

1. Реализовать и проверить транспорт, реестр, общую подготовку и Go-рендер; существующие HTTP формы, SQL `001`–`008` и хранимые снимки не изменять.
2. Прогнать изолированные fixtures единственной PostgreSQL, native UI/MCP и штатный Linux container smoke. Зафиксировать хеши старых JSON/UUID/migrations и отсутствие новых внешних вызовов от чтения/экспорта.
3. Документировать и проверить включённый по умолчанию MCP без Authorization на 8080 и 18088, открытый CORS, произвольный Host/Origin и отсутствие влияния старого QAG_MCP_TOKEN. Не добавлять реальные credentials в артефакты репозитория.
4. Для доставки проверить отсутствие активных рабочих прогонов, сохранить backup с исходным ключом и конфигурацией, обновить Compose без удаления томов. MCP включается по умолчанию без авторизации; функциональная приёмка выполняется на изолированных данных, рабочая проверка использует только discovery/чтение.
5. Проверить readiness, UI, прежнюю историю и контрольные суммы данных. Откат: прежний образ и конфигурация на тех же томах, удаление MCP env override; schema rollback не требуется. Артефакты/срезы в памяти после restart готовятся заново, работающие целевые запросы автоматически не возобновляются.
