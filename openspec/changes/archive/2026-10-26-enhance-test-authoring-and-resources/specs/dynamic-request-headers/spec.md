## Purpose

Источники заголовков получают значение из JSON отдельного HTTP-запроса, позволяя использовать токены и другие вычисляемые значения в HTTP-вызовах и gRPC-метаданных без ручного копирования.

## ADDED Requirements

### Requirement: Настройка значения из HTTP-запроса

Заголовок HTTP-запроса, gRPC-метаданные и общий заголовок соответствующего ресурса SHALL поддерживать обычное значение либо значение из HTTP-источника. Источник SHALL задавать HTTP-метод, абсолютный URL, query, обычные заголовки, необязательное текстовое или JSON-тело, TLS/mTLS, поле JSON и необязательный префикс значения. При создании такого заголовка SHALL выбираться режим «Перед каждым вызовом» либо «Один раз на прогон». Настройка MUST не требовать создания отдельного HTTP-ресурса. Заголовки запроса самого источника MUST не содержать вложенные HTTP-источники.

#### Scenario: Получение токена через POST
- **WHEN** пользователь настраивает POST с JSON-телом, поле `/data/access_token`, префикс `Bearer ` и режим получения
- **THEN** основной запрос использует значение `Bearer ` с извлечённым токеном

#### Scenario: Обычный заголовок
- **WHEN** заголовок использует статическое значение или существующую подстановку переменной
- **THEN** он работает по прежним правилам без дополнительного HTTP-запроса

### Requirement: Однозначное извлечение JSON-поля

Поле SHALL задаваться JSON Pointer с поддержкой вложенных объектов, индексов массивов и экранирования имён. Источник SHALL принимать только полный ответ 2xx с корректным JSON. Извлекаемое значение SHALL быть строкой, числом или boolean; число MUST преобразовываться без округления. Отсутствующее поле, `null`, объект, массив, повреждённый JSON или недопустимый указатель MUST завершать подготовку ошибкой. CR/LF в итоговом значении заголовка MUST отклоняться до основного запроса.

#### Scenario: Вложенное поле массива
- **WHEN** указатель `/tokens/0/value` адресует строковое поле первого элемента массива
- **THEN** заголовок получает именно это значение

#### Scenario: Точное числовое значение
- **WHEN** поле содержит число `9007199254740993123`
- **THEN** значение заголовка сохраняет все цифры без преобразования через неточный формат

#### Scenario: Поле отсутствует или непригодно
- **WHEN** указатель не найден либо указывает на `null`, объект или массив
- **THEN** попытка сообщает об ошибке извлечения и основной запрос не отправляется

#### Scenario: Недопустимые переносы строк
- **WHEN** извлечённое значение с префиксом содержит CR или LF
- **THEN** приложение отклоняет заголовок и не отправляет основной запрос

### Requirement: Получение перед каждым вызовом

В режиме «Перед каждым вызовом» каждая новая осознанная попытка основного блока SHALL получать значение заново. Значение MUST не переиспользоваться между попытками или прогонами. Повтор доставки той же команды MUST возвращать ту же попытку без повторного обращения к источнику.

#### Scenario: Две осознанные попытки
- **WHEN** пользователь дважды запускает блок с режимом «Перед каждым вызовом»
- **THEN** источник вызывается по одному разу для каждой новой попытки и каждый основной запрос использует своё значение

#### Scenario: Повтор команды
- **WHEN** команда запуска доставлена повторно с тем же ключом
- **THEN** дополнительный запрос источника и дополнительный основной вызов не выполняются

### Requirement: Переиспользование в пределах прогона

В режиме «Один раз на прогон» первый успешно извлечённый результат конкретной настройки заголовка SHALL переиспользоваться последующими вызовами в том же прогоне. Кэш MUST различать прогоны и настройки заголовков и MUST не передавать значения другому прогону. Ошибка получения MUST не кэшироваться как успешное значение; новая явная попытка SHALL позволять повторное получение. Автоматическое обновление или повтор из-за истечения срока токена MUST не выполняться.

#### Scenario: Общий заголовок нескольких блоков
- **WHEN** два блока используют один общий заголовок ресурса с режимом «Один раз на прогон»
- **THEN** после первого успешного получения второй блок использует то же значение без нового обращения к источнику

#### Scenario: Следующий прогон
- **WHEN** пользователь начинает другой прогон с той же настройкой
- **THEN** источник получает новое значение при первом выполняемом блоке этого прогона

#### Scenario: Явный повтор после отказа
- **WHEN** источник завершился ошибкой, а пользователь повторно запускает основной блок
- **THEN** новая попытка вправе заново обратиться к источнику и не использует ошибку как значение заголовка

### Requirement: Источник при пробном запуске

Пробный вызов редактора SHALL получать значение в рамках своей попытки независимо от выбранного режима. Он MUST не использовать кэш какого-либо прогона и MUST не наполнять его. Выполнение источника MUST не создавать отдельный прогон тест-кейса.

#### Scenario: Два пробных запуска
- **WHEN** пользователь дважды пробно запускает блок с настройкой «Один раз на прогон»
- **THEN** каждый пробный запуск получает собственное значение, а история первых прогонов не изменяется

### Requirement: Ошибки и ограничения источника

Источник SHALL выполняться на сервере в пределах отмены и общего тайм-аута основной попытки с лимитом ответа 5 MiB. Перенаправления и автоматические повторы MUST быть отключены. Ошибка соединения, TLS, HTTP-статус вне 2xx, усечение или ошибка извлечения MUST останавливать основной вызов. UI SHALL показывать этап и безопасную причину отказа, отличая источник от основного сервиса.

#### Scenario: Источник вернул ошибку
- **WHEN** источник ответил 401, 302 или недоступен
- **THEN** основной запрос не отправляется, а интерфейс показывает отказ получения заголовка без перехода по Location

#### Scenario: Отмена получения
- **WHEN** пользователь отменяет попытку во время запроса источника
- **THEN** его запрос отменяется в рамках той же попытки и основной запрос не начинается

### Requirement: Секретность полученных значений

Извлечённое значение SHALL считаться секретом независимо от имени заголовка. Оно и его полное значение с префиксом MUST маскироваться в ответах, ошибках, различиях и журналах. Полное тело ответа источника и полученное значение MUST не сохраняться в публичном снимке, истории или открытом виде в БД. Настройки SHALL содержать ссылки на сохранённые секреты; такие ссылки SHALL поддерживаться в заголовках и теле запроса источника, но MUST не допускаться в URL и query. Секреты MUST не читаться из произвольного окружения процесса.

#### Scenario: Основной сервис отражает токен
- **WHEN** основной сервис возвращает извлечённый токен в JSON, заголовке или тексте ошибки
- **THEN** API, интерфейс и сохранённый результат маскируют токен и не раскрывают ответ источника

#### Scenario: Учётные данные в теле источника
- **WHEN** JSON-тело источника ссылается на секрет окружения или ресурса
- **THEN** значение подставляется только при выполнении, а сохранённая конфигурация и история содержат ссылку вместо секрета
