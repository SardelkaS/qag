## MODIFIED Requirements

### Requirement: Единый локальный демонстрационный сервис

qag SHALL предоставлять демонстрационные HTTP- и unary gRPC-интерфейсы как часть обычного запуска приложения. Оба интерфейса MUST читать одну демонстрационную запись из PostgreSQL и возвращать согласованные идентификатор, название, статус и точную сумму. В нативном режиме демонстрационные адреса SHALL быть доступны только через loopback. В контейнерном режиме HTTP SHALL быть доступен через общий локально опубликованный порт qag, а gRPC SHALL быть доступен исполнителю запросов на loopback внутри контейнера без обязательной публикации порта. SQL-ресурс SHALL использовать то же PostgreSQL-хранилище под отдельной ограниченной ролью с адресом, достижимым из контейнера. Отдельный запуск сервиса пользователем MUST не требоваться.

#### Scenario: Согласованное чтение через два протокола
- **WHEN** пользователь запрашивает существующую демонстрационную запись через HTTP и gRPC
- **THEN** оба ответа содержат одинаковые значения из одной записи PostgreSQL

#### Scenario: Запуск штатной сборки
- **WHEN** пользователь запускает настроенную готовую сборку qag
- **THEN** демонстрационные HTTP и gRPC доступны вместе с приложением без дополнительного процесса или контейнера

#### Scenario: Прохождение примера в Docker
- **WHEN** пользователь открывает опубликованный Web UI контейнерной установки и выполняет встроенный пример
- **THEN** HTTP, gRPC и SQL-блоки используют достижимые внутренние адреса и читают согласованную запись без запуска отдельного демонстрационного контейнера
