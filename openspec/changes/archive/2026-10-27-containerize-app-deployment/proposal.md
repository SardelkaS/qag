## Why

Сейчас Docker Compose поднимает только PostgreSQL, а приложение приходится собирать и запускать на Windows с установленными Go и Node.js. Нужен единый контейнерный запуск приложения и БД с готовым адресом Web UI, короткими командами Makefile и понятной инструкцией перехода для существующей установки.

## What Changes

- Добавить многоэтапный Dockerfile: сборка TypeScript UI и Linux-бинарника Go, готовый runtime с UI, иконками, шрифтами и доверенными CA, а также `.dockerignore` для локальных данных и артефактов.
- Сделать Docker Compose основным способом запуска: контейнер qag, один PostgreSQL, автоматическая подготовка постоянной конфигурации и ограниченной demo-роли, ожидание готовности и корректная остановка.
- Публиковать HTTP на `127.0.0.1:8080` с настраиваемым внешним портом. Разрешить явный контейнерный сетевой режим, сохранив проверку Host/Origin/CSRF и локальный доступ с хоста.
- Хранить мастер-ключ, пароли и PKI вне образа и БД; сохранять их вместе с существующим PostgreSQL-томом при пересоздании контейнеров. Для прежней установки предусмотреть явный импорт `.local/dev.env` и PKI с сохранением ключа и данных.
- Добавить Makefile с командами подготовки, сборки, запуска, остановки, перезапуска, просмотра статуса и логов. Make остаётся необязательной оболочкой над доступными напрямую командами Docker Compose.
- Обновить README: быстрый запуск только с Docker, вариант с Make, адрес браузера, смена порта, переход с прежнего запуска и режим разработки. Уточнить эксплуатационные инструкции по backup и адресам ресурсов из контейнера.

## Capabilities

### New Capabilities

- `container-deployment`: контейнерная сборка и запуск, опубликованный порт, постоянная конфигурация, переход существующей установки и команды Makefile.

### Modified Capabilities

- `local-app-runtime`: контейнерный сетевой режим, зависимость старта от подготовки БД и конфигурации, инструкции Docker/Make при сохранении нативного режима разработки.
- `local-demo-service`: доступность встроенного примера и правильные внутренние адреса его HTTP/gRPC/SQL-ресурсов в контейнере.

## Impact

Будут затронуты новые `Dockerfile`, `.dockerignore`, `Makefile`, текущий `compose.yaml`, конфигурация и старт в `internal/runtime`, `cmd/qag`, проверка адресов в `internal/httpapi`, подготовка конфигурации/ролей/PKI и Windows-скрипты совместимости. README и `docs/operations.md` должны описывать оба способа запуска и сохранение исходных реквизитов. Потребуются проверки образа, сетевых ограничений, чистой и повторной подготовки, импорта и встроенного примера на существующем PostgreSQL-стенде.

Изменение не требует новой схемы БД или второго PostgreSQL для тестов. Контейнер остаётся однопользовательским локальным приложением; доступ из LAN/интернета и авторизация не входят в задачу. Используется существующий browser HTML clipboard для Linux-backend; native Windows clipboard остаётся возможностью нативного Windows-запуска.
