## Purpose

Консольная поставка позволяет установить самостоятельный qag средствами Go, запустить Web UI и MCP с выбранным хранилищем и переносить данные без checkout репозитория или frontend-инструментов.

## ADDED Requirements

### Requirement: Установка самостоятельного приложения через Go

Пользователь SHALL устанавливать qag командой `go install github.com/SardelkaS/qag/cmd/qag@<version>`, включая `@latest` для опубликованной версии. Установленный бинарник SHALL содержать готовые Web UI, иконки и шрифты отчётов. Установка и работа MUST не требовать Node.js, npm, PowerShell, Docker, исходников рядом с бинарником или отдельного скачивания UI. Поддерживаемые нативные платформы SHALL включать Windows, Linux и macOS; требуемая версия Go и каталог установки SHALL быть описаны в README.

#### Scenario: Установка вне репозитория
- **WHEN** пользователь устанавливает опубликованную версию в чистом окружении с поддерживаемым Go без Node.js и checkout
- **THEN** в Go bin-каталоге появляется `qag`, который запускает готовый UI, favicon и MCP и формирует серверный отчёт с кириллицей

#### Scenario: Запуск после перемещения бинарника
- **WHEN** бинарник перенесён в другой каталог и запущен из произвольной рабочей директории
- **THEN** UI и шрифты доступны без обращения к `web/dist` или другим файлам исходного репозитория

### Requirement: Консольный запуск и справка

CLI SHALL предоставлять `qag serve`, `qag data export`, `qag data import`, `--help` и `--version`. Вызов `qag` без подкоманды SHALL означать запуск сервера, а прежняя команда `qag healthcheck` SHALL сохраняться. Сервер SHALL работать на переднем плане, выводить адрес UI/MCP и вид хранилища без секретов и корректно завершаться по interrupt/SIGTERM. Справка SHALL объяснять параметры и примеры. Неизвестная команда, флаг или лишний аргумент MUST приводить к ненулевому коду до изменения данных; справка и версия MUST не открывать хранилище.

#### Scenario: Быстрый файловый запуск
- **WHEN** пользователь выполняет `qag` без настройки хранилища
- **THEN** сервер запускается с `./qag.yaml` и выводит локальный адрес браузера и MCP

#### Scenario: Справка при недоступной БД
- **WHEN** в окружении задана недоступная БД, а пользователь вызывает `qag --help` или `qag --version`
- **THEN** команда успешно завершается без подключения к БД и без создания YAML

#### Scenario: Неизвестный параметр
- **WHEN** пользователь передаёт неподдерживаемый флаг
- **THEN** CLI показывает безопасную ошибку и usage, возвращает ненулевой код и не запускает сервер

### Requirement: Явный выбор хранилища и конфигурации

CLI SHALL принимать `--storage postgres|yaml`, `--data-file`, `--database-url`, `--demo-database-url`, `--secret-key`, `--address` и `--config` в соответствующих командах. Флаги SHALL иметь приоритет над переменными процесса, переменные — над приватным файлом конфигурации; SHALL поддерживаться существующие `QAG_*` и новые `QAG_STORAGE`/`QAG_DATA_FILE`. Явный выбор backend SHALL исключать проверку неиспользуемого подключения другого backend. Без явного backend файловая настройка SHALL выбирать YAML, настройка подключения — PostgreSQL, отсутствие обеих — YAML `./qag.yaml`; одновременно заданные конфликтующие селекторы MUST требовать явного выбора либо исправления. Явные флаги `--data-file` и `--database-url` MUST не приниматься вместе. Ошибка PostgreSQL MUST не вызывать переключение на YAML.

#### Scenario: Прежний контейнерный запуск
- **WHEN** Compose передаёт прежние подключения и мастер-ключ без нового параметра storage
- **THEN** запускается PostgreSQL-режим с прежними данными и не создаётся YAML-файл

#### Scenario: Явный YAML при старых env-параметрах
- **WHEN** пользователь выбирает `--storage yaml --data-file work.yaml`, сохранив PostgreSQL-переменные в окружении
- **THEN** открывается только `work.yaml`, а PostgreSQL и её demo-роль не требуются

#### Scenario: Ошибочный DSN
- **WHEN** пользователь выбрал PostgreSQL, но подключение невалидно либо недоступно
- **THEN** запуск завершается с ненулевым кодом без печати пароля и без создания резервного файлового состояния

### Requirement: Файл данных при запуске

`qag serve --data-file <path>` SHALL открывать указанный YAML как основное изменяемое хранилище, а не однократный импорт. Относительный путь SHALL разрешаться от текущей директории. Отсутствующий файл SHALL создаваться после успешной проверки параметров в существующем каталоге; имеющийся файл SHALL проверяться целиком до готовности. Ошибочный, неподдерживаемый или недоступный файл MUST не заменяться пустым. YAML-режим MUST не требовать PostgreSQL, demo-DSN или мастер-ключ PostgreSQL.

#### Scenario: Открытие перенесённого файла
- **WHEN** пользователь запускает qag с экспортированным YAML на другой машине
- **THEN** каталог, изображения, ресурсы и история доступны из этого файла, а новые сохранения записываются туда же

#### Scenario: Ошибка чтения
- **WHEN** выбранный файл повреждён либо недоступен
- **THEN** сервер не объявляет готовность, исходные байты сохраняются и новый пустой файл вместо него не создаётся

### Requirement: Автономные команды переноса

`qag data export <параметры-хранилища> --output <path>` SHALL сохранять переносимый YAML. `qag data import <параметры-хранилища> --input <path>` SHALL объединять его с целевым хранилищем; `--dry-run` SHALL выполнять те же проверки без записи. Команды SHALL работать без запуска UI/MCP, demo-listeners и внешних вызовов. Экспорт MUST не перезаписывать существующий output; input MUST не совпадать с живым файлом назначения. Успех SHALL возвращать код 0 и безопасные счётчики, конфликт/ошибка — ненулевой код. Содержимое YAML и секреты MUST не выводиться в stdout/stderr.

#### Scenario: PostgreSQL в файл и обратно
- **WHEN** пользователь экспортирует PostgreSQL в новый YAML и импортирует его в другую подготовленную PostgreSQL с её мастер-ключом
- **THEN** переносятся все данные согласно `portable-data-transfer`, без запуска сервера и копирования исходного ключа

#### Scenario: Проверка объединения
- **WHEN** пользователь вызывает import с `--dry-run` для заполненного назначения
- **THEN** получает число новых и одинаковых записей либо перечень конфликтующих сущностей/ID, а назначение не изменяется
