## Why

Ручные проверки требуют одновременно вести тест-кейсы, выполнять запросы в отдельных инструментах и сопоставлять ответы с ожиданиями. qag объединит эти действия в локальном Web UI: тестировщик проходит шаги вручную, а приложение выполняет HTTP-, gRPC- и PostgreSQL-вызовы и показывает различия результатов.

## What Changes

- Создать приложение на Go и TypeScript для одного локального пользователя без авторизации; хранить каталог, настройки и прогоны в PostgreSQL.
- Разместить слева раскрываемые папки с тест-кейсами и вкладки «Активные» / «Архив». Папки сортировать по алфавиту; активные тест-кейсы сортировать по алфавиту перед архивными, которые показываются тусклым цветом.
- Поддержать создание, переименование, архивирование и восстановление папок и тест-кейсов. Архивирование папки переносит её целиком на вкладку архива, сохраняя собственный статус каждого тест-кейса.
- Открывать выбранный тест-кейс в центральном редакторе. Дать возможность создавать и редактировать последовательность шагов с необязательным заголовком, описанием и несколькими блоками вызовов.
- Настраивать ресурсы отдельно для выбранного окружения: HTTP/gRPC-адреса, PostgreSQL-подключения, заголовки, секреты и TLS/mTLS-сертификаты. Поддержать ссылки вида `AI_GW_SERVISE/task`, где имя ресурса разрешается в адрес и настройки подключения при запуске.
- Выполнять каждый блок по его кнопке: HTTP-запрос, unary gRPC-вызов или SQL-запрос PostgreSQL с параметрами. Выводить статус, длительность, данные и ошибки, а рядом — ожидаемый результат и различия.
- Поддержать ручной прогон тест-кейса со статусами шагов, комментариями и результатами вызовов. Сохранять неизменяемый снимок сценария, чтобы редактирование тест-кейса не переписывало историю.
- Автоматически отмечать для сохранения первый завершённый прогон и первый успешный прогон каждого тест-кейса; позволять сохранить любой другой прогон кнопкой. Показывать причины сохранения, сохранённую историю и недавние несохранённые прогоны.

### Границы и принятые допущения

Подтверждены пользователем локальный режим, PostgreSQL как хранилище и единственная SQL-цель, а также правила сохранения прогонов. Предлагаемые детали первой версии:

- Папки одного уровня. Алфавитная сортировка относится к каталогам; шаги и блоки сохраняют порядок сценария, заданный автором.
- UI и документы на русском. Сохраняются идентификаторы, служебный синтаксис запросов и названия протоколов.
- Прогоны запускаются для одного тест-кейса; пользователь сам запускает каждый блок и отмечает ручные шаги. Запуск отдельного блока из редактора не считается полным прогоном.
- Первый прогон определяется по порядку завершения, а первый успешный — по первому результату `passed`, за всю жизнь тест-кейса. Один прогон может иметь обе причины сохранения.
- Несохранённые прогоны тоже записываются в PostgreSQL и доступны после перезапуска до явной очистки пользователем. Автоматического удаления по сроку в первой версии нет.
- Архивные объекты доступны для просмотра и истории; для редактирования и нового прогона их нужно восстановить.
- Для gRPC поддержать unary-методы с reflection или загруженными `.proto` и зависимостями. Streaming, произвольные скрипты, пакетный автозапуск, расписания, CI, многопользовательский режим и другие СУБД в эту версию не входят.

## Capabilities

### New Capabilities

- `test-case-catalog`: папки, тест-кейсы, раскрываемая навигация, алфавитная сортировка и архив.
- `test-case-authoring`: редактор шагов и типизированных блоков вызовов, ожидания, сохранение и версии сценария.
- `resource-environments`: окружения, именованные ресурсы, переменные, секреты и параметры TLS/mTLS.
- `call-execution`: исполнение HTTP, unary gRPC и PostgreSQL на Go-сервере, ограничения, отмена и результаты.
- `result-comparison`: сопоставление ожидаемого и фактического результата, различия и признаки неполноты.
- `test-run-history`: ручные прогоны, снимки сценариев, статусы, автоматическое и ручное сохранение истории.
- `local-app-runtime`: локальный Web UI, PostgreSQL-хранилище, миграции, перезапуск и диагностика запуска.

### Modified Capabilities

Нет: существующих спецификаций и прикладного кода в репозитории нет.

## Impact

- Предстоит создать Go-сервер с API и исполнителями протоколов, TypeScript-клиент и схему PostgreSQL. Существующие продуктовые API и данные не затрагиваются.
- PostgreSQL приложения отделён от PostgreSQL-ресурсов тестирования; креденшелы целевых систем не выдаются браузеру. HTTP, gRPC и SQL выполняются сервером с выбранными настройками ресурса.
- Предлагаемый клиент — React + TypeScript + Vite, сервер — Go с PostgreSQL-драйвером и gRPC/Protobuf-библиотеками. Детали модулей, схемы и проверок приведены в `design.md` и `tasks.md`.
- Нужны локальный PostgreSQL, конфигурация подключения приложения и ключ для шифрования сохранённых секретов. Для интеграционных проверок понадобятся изолированные HTTP-, gRPC- и PostgreSQL-стенды.
- В этом изменении подготавливаются документы; реализация начинается отдельным этапом apply.
