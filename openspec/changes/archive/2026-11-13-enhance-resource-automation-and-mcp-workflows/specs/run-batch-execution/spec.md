## MODIFIED Requirements

### Requirement: Отказы хранения и перезапуск

Начало очереди и каждой попытки MUST устойчиво сохраняться до сети. Если результат внешнего вызова не подтверждён выбранным хранилищем, очередь MUST ожидать сохранения и повторять только запись; следующий вызов MUST не начинаться. При потере Go-процесса очередь и незавершённый прогон SHALL становиться `interrupted` без автоматического продолжения либо повтора запросов. Сохранённые данные и правила first_run/first_success/manual MUST сохраняться с учётом явно заданной политики закрепления прогона. Те же гарантии SHALL применяться к очереди выбранного шага; восстановление MUST сохранять её выборку и не продолжать её автоматически.

#### Scenario: Отказ записи результата
- **WHEN** внешний вызов выполнен, но сохранение его результата отклоняется
- **THEN** следующий блок не запускается и уже отправленный запрос не повторяется при восстановлении БД

#### Scenario: Потеря процесса
- **WHEN** Go-процесс останавливается посреди очереди
- **THEN** после запуска видны прерванная очередь и прогон с прежними результатами, а внешние запросы не повторяются

## ADDED Requirements

### Requirement: Последовательное выполнение выбранного шага

Для активного прогона SHALL быть доступна MCP-команда выполнения всех исходных блоков одного stepId из зафиксированного сценария. Очередь SHALL устойчиво сохранять выбор шага, порядок блоков и ключ команды до сети, возвращая быстро доступный ID/прогресс. Остальные шаги и исследовательские варианты MUST не выполняться; ручные статусы и завершение MUST не выставляться автоматически. Ошибка блока SHALL сохраняться с продолжением следующего по прежним правилам; подтверждённая отмена SHALL останавливать остаток очереди. Одновременная другая очередь/попытка и неизвестный/чужой шаг MUST отклоняться без частичного запуска.

#### Scenario: Шаг с несколькими блоками
- **WHEN** клиент выбирает шаг с HTTP и gRPC из активного прогона
- **THEN** выполняются только эти блоки по порядку, а ранее/позднее расположенные шаги не вызываются

#### Scenario: Ручной шаг
- **WHEN** выбранный шаг не содержит блоков
- **THEN** очередь завершается с нулём вызовов без фиктивной попытки или отметки passed

#### Scenario: Чужой шаг
- **WHEN** stepId отсутствует в снимке этого прогона
- **THEN** команда возвращает ошибку до регистрации внешних действий

#### Scenario: Повтор потерянного ответа
- **WHEN** команда очереди шага повторена с тем же ключом и параметрами
- **THEN** возвращается прежняя очередь без повторных источников или запросов

#### Scenario: Новый явный повтор
- **WHEN** предыдущая очередь завершена и клиент выбирает тот же шаг с новым ключом
- **THEN** создаётся новая очередь и новые номера попыток, прежние результаты остаются

#### Scenario: Не весь кейс проверен
- **WHEN** выполнен только один шаг, а другие остались not_run
- **THEN** обычное завершение не считает весь кейс пройденным
