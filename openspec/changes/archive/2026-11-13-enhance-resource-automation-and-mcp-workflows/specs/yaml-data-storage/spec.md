## MODIFIED Requirements

### Requirement: Полное файловое состояние приложения

YAML-режим SHALL сохранять папки и архив, кейсы и порядок шагов, изображения, окружения и их версии, ресурсы и их версии/секреты, proto bundles, прогоны и снимки, ручные статусы/комментарии, все сохранённые попытки, варианты/версии, очереди/элементы, ключи идемпотентности и демонстрационные данные. Все предметные действия UI и MCP SHALL работать с одним выбранным состоянием по прежним правилам revision, readOnly, сортировки, сохранения первых прогонов, маскирования и оценки. SQL-ресурсы пользователей SHALL обращаться к явно настроенным внешним PostgreSQL независимо от backend приложения.

Устойчивое состояние SHALL включать определения переменных ресурса и их HTTP-источников, historyPolicy прогона и выбор шага в очереди. Прогоны без закрепления SHALL сохраняться целиком наравне с остальными; полученные HTTP-значения и кеш MUST не становиться частью файла.

#### Scenario: Изменение через MCP и чтение в браузере
- **WHEN** MCP создаёт окружение и кейс, а пользователь открывает UI того же YAML-процесса
- **THEN** UI видит эти записи, а после перезапуска сохраняются их ID, revision и значения

#### Scenario: История с вариантами и эталонами
- **WHEN** пользователь сохраняет прогон с изображением, очередью, комментариями и исследовательскими попытками и перезапускает qag
- **THEN** прежняя история и все версии доступны в UI, MCP и экспорте отчёта без подстановки текущего сценария

#### Scenario: Внешняя SQL-цель
- **WHEN** YAML-приложение выполняет пользовательский SQL-блок с явно настроенным PostgreSQL-ресурсом
- **THEN** запрос выполняется на этом ресурсе и результат сохраняется в YAML без служебной PostgreSQL приложения

#### Scenario: Перезапуск новых возможностей
- **WHEN** YAML содержит ресурс с HTTP-переменной, завершённый unretained и очередь шага
- **THEN** определения, политику, исходные ID и сохранённые результаты можно прочитать после перезапуска без повторного получения значения

### Requirement: Версионированный самодостаточный YAML

Файл SHALL иметь явные идентификатор формата и версию и содержать все данные внутри одного UTF-8 YAML-документа. Изображения SHALL храниться с метаданными, SHA-256 и base64-байтами; сертификаты и proto bundles — содержимым. Точные JSON/SQL-числа, NULL, пустая строка, временные метки, ID и порядок значимых массивов SHALL сохраняться без преобразования через float. Документ SHALL использовать тот же формат, что экспорт `portable-data-transfer`, без ссылок на файлы исходной установки. Запись SHALL иметь устойчивый порядок коллекций/ключей; повторное сохранение неизменённого состояния MUST не менять его предметное содержимое.

Новая версия qag SHALL читать форматы v1 и v2, а новые файлы/экспорты и последующие подтверждённые записи SHALL использовать v2. Отсутствующие в v1 поля SHALL означать auto, очередь всего кейса и пустой набор локальных переменных. Нормализация MUST не переписывать raw JSON прежних снимков и результатов. Само чтение/экспорт MUST не обновлять исходный файл; неизвестные версии SHALL по-прежнему отклоняться.

#### Scenario: Перенос одного файла
- **WHEN** YAML скопирован без исходного каталога и конфигурации на другую машину
- **THEN** изображения и исторические версии ресурсов читаются, а настроенные секреты доступны исполнителю при достижимости внешних адресов

#### Scenario: Точное значение
- **WHEN** результат содержит `9007199254740993123.125`, SQL NULL и пустую строку
- **THEN** после записи, чтения и переноса каждое значение сохраняет исходный тип и точное представление

#### Scenario: Старый файл
- **WHEN** передан корректный v1 с прежними прогонами и ресурсами
- **THEN** он читается с совместимыми default-полями без потери истории, а первая реальная запись атомарно создаёт v2

#### Scenario: Только экспорт старого файла
- **WHEN** v1 используется источником data export
- **THEN** выход имеет v2, а байты исходного v1 не изменяются

### Requirement: Секреты в приватном файле

Самодостаточный YAML SHALL хранить сохранённые секреты подключений открытыми значениями и MUST не требовать отдельного мастер-ключа для их использования. Создаваемый файл и временные файлы SHALL быть доступны только текущему пользователю средствами поддерживаемой ОС. CLI и README SHALL явно сообщать, что YAML содержит секреты и приватные ключи; содержимое MUST не печататься. UI/MCP, история, отчёты и обычные журналы SHALL сохранять прежнее маскирование. Полученные динамические значения заголовков и HTTP-переменных MUST не добавляться в файл как новые секреты.

Файл SHALL хранить лишь определения HTTP-переменных и безопасную диагностику попыток; тела источников и выбранные значения MUST отсутствовать, включая прогоны unretained.

#### Scenario: Сохранение токена
- **WHEN** пользователь сохраняет секрет ресурса в YAML-режиме и повторно открывает ресурс через UI или MCP
- **THEN** файл хранит пригодное исполнителю значение, а ответ интерфейса показывает только факт наличия секрета

#### Scenario: Частный доступ
- **WHEN** qag создаёт YAML с секретами
- **THEN** файл и его промежуточные копии имеют приватные права текущего пользователя без печати значений в консоль
